Offline access

190 TOOLS

Transmute keeps a copy of its own code — the HTML, scripts, styles and fonts that draw a page — so a page opens without waiting on the network. The engines are deliberately not part of that copy. None of them is ever fetched in the background, and none is stored unless you ask for it here, by name, with its size in front of you.

For 12 audio tools, FFmpeg is decided per file. Those tools hand your file to the browser’s own audio decoder first, and only reach for the 30.8 MBcore if that decoder refuses it. Which files get refused differs between Safari, Chrome and Firefox, and between versions of each. So they are neither “works offline” nor “doesn’t” — an m4a that one browser opens on its own is an m4a another sends to FFmpeg. Storing the core is what makes the answer the same every time.

Reading what is stored…

That removes both caches this site owns: every engine you stored, and the copy of the site’s own pages. It does not touch transmute-recent-outputs, the single localStorage key that remembers the names of your last eight downloads — that is a different thing in a different store, and clearing site data in your browser is what removes it. It also leaves the service worker registered, so your next visit will keep the two pages it precaches: the home page and the offline notice. No engine comes back without you asking again.

What offline does not cover

THE HONEST EDGES
  • A tool's own code arrives as a chunk of JavaScript that is cached the first time you open that tool's page. Store every engine here and a page you have never visited will still want the network once.
  • Browsers evict storage as a whole, not in pieces, and they do it without telling the page. What is stored today may be gone tomorrow — which is why this page re-reads rather than remembering, and why a tool never claims an engine it has not checked for.
  • This is per browser, per device, per profile. Storing FFmpeg here does nothing for your phone, and nothing for a private window.
  • 142 of the 190 tools reach no engine at all — they run on Canvas, Web Audio, WebCodecs and ordinary JavaScript. There is nothing to store for them and nothing missing when you are offline.
  • A page served from the cache is the page as it was when you last loaded it. Pages are always fetched from the network first and only fall back to a stored copy when the network genuinely fails, so a stale one can only appear when you are actually offline.
