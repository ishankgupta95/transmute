2d:T91a,This tool joins clips end to end and never re-encodes anything, which means it is fast and lossless and also means it cannot join everything. The clips are copied into one file exactly as they are, so they have to share a video codec, a frame size, a pixel format, an audio codec, sample rate and channel count — or all be silent — a container the copy can be written into, and the timing base that container counts in. Two MP4s that agree on everything else and count time differently were measured on this build to produce a join whose picture runs out of step with its own sound, so that is checked too. Anything that does not match is refused, by file name and by the property that differs, before a single byte is written. That refusal is the point of the page rather than an error path, and there is a measurement behind it. FFmpeg's concat demuxer, handed clips that do not match, does not fail: it reports success and writes a file with clips missing. Measured on the build this page runs, an MP4 and an MKV holding identical H.264 video at the same size and pixel format with identical AAC audio produced exit code zero and a file containing only the first clip. Nothing in that pair differs except the container and the timing base it counts in — 1/57600 against 1/1000, measured side by side — which is why both are checked as well as everything inside them. Two independent guards enforce this. Every clip is read as it lands and compared against the first, so the mismatch table appears while you are still building the queue; and the join itself re-checks for the same reasons and then measures the finished file against the total length of its parts, failing if it comes up short or runs long. There is deliberately no fall back to re-encoding.
