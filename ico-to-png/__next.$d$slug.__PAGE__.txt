4f:T71f,An .ico is not one picture — it is a container holding several, typically 16 × 16, 32 × 32 and 48 × 48, sometimes a 256 × 256 as well. That matters because a browser handed the whole file decodes exactly one image out of it and never says which; the decoders in Chromium and WebKit prefer the largest size, then the greatest colour depth, and nothing in the platform lets a page ask for a different one. So the usual one-line convert quietly throws away most of what you gave it. This page reads the icon directory instead — six bytes of header and sixteen per entry — lists every image the file actually contains with its size and bit depth, and lets you take the ones you want. The directory also tells the page how each icon is stored, which decides what can honestly be claimed about it. An entry stored as a PNG is copied straight out as a byte slice: no decode, no canvas, no re-encode, so the file you get is byte for byte the one that was inside, and that is genuinely lossless. An entry stored as a bitmap cannot be, because a bitmap is not a PNG; it is decoded and written out again. Each icon is badged with which of the two it is, read out of the directory rather than guessed from the file's name, because one .ico can carry both kinds side by side. Files made by this site's own PNG to ICO tool store every entry as a PNG, so they round-trip through here untouched. Cursor files (.cur) use the identical container and work the same way, with the caveat that the hotspot coordinates a cursor carries are not part of a PNG and are dropped.
