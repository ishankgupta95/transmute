3c:T818,Start with the part every other page about this leaves out. A PDF permission flag is not a lock. It is a value written into the document saying what the author intends to allow — printing, editing, copying text — and a well-behaved reader honours it by greying the menu items out. Nothing enforces it. A reader that does not care ignores it, and any tool that can open the file can clear the flags outright, which for a document that opens without a prompt means with no password at all. This site ships that tool one page over, at Unlock PDF. We would rather say so here than sell you the opposite. So what is this good for? The ordinary case, which is most cases: telling colleagues, and their software, that this copy is the read-only one — that the printable version is elsewhere, that the figures are not to be lifted into a slide deck, that this is not the file to edit. That is a real thing to communicate and it is what the flags were designed for. They stop accidents, not adversaries. Three controls are offered because three are all that do anything. Printing can be allowed in full, restricted to low resolution, or denied outright. Editing runs from everything allowed down through annotations, form filling and page assembly to nothing. Copying text and graphics can be denied. The accessibility flag the format also defines is deliberately not offered: at the encryption revision this tool writes, setting it changes the permission bits not at all, so a checkbox for it would be a control that does nothing — which is worse than an absent one. The document stays openable by anyone. The restrictions are written into the encryption dictionary alongside an owner password, with the user password left empty, and that is the shape that lets any reader open the file while still recording what it may do with it.
