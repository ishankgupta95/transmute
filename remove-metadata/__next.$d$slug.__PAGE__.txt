A PDF carries an /Info dictionary — title, author, subject, keywords, the application that wrote it and the dates it was written — and often one or more XMP packets, which repeat much of that in XML and frequently travel inside embedded photographs as well. A photo carries EXIF: the camera and lens, the exposure, the timestamp, and on a phone the GPS coordinates of wherever you were standing. This page takes either kind of file, lists what it can read, and hands back a cleaned copy in a single press — the run saves the file for you, so there is no second button to hunt for. The two paths work differently, and the difference matters. For a PDF, every key in the /Info dictionary is deleted rather than blanked, and every XMP packet found on the catalog, on a page or on an embedded image goes with it; clearing the properties alone would leave the XMP still naming you. The pages are untouched, so the document looks and prints exactly as it did — which also means a name typed into a page is still on that page. For an image there is no way to cut the tags out. The picture is decoded, drawn onto a canvas and encoded again, and the metadata is simply not carried across, so the download is a new picture built from your pixels. Keep your original if you need the pixels untouched. After every run the cleaned file is read again by the same reader that listed the source, and the page prints what is left, so what you get is a measurement rather than a promise.
