5a:T806,A PDF is a pile of objects plus a table saying where in the file each one lives. When a download is interrupted, a program crashes mid-save, or something writes the file with its arithmetic wrong, that table stops matching the objects and readers start refusing the document — sometimes with a message about a damaged file, sometimes by opening a blank page. This tool hands the file to qpdf, compiled to WebAssembly and run in your tab. qpdf parses it, hunts down the objects by scanning the file when the table cannot be trusted, and writes out a fresh document with a rebuilt cross-reference table. There is nothing to configure, because the rewrite is the repair. Now be exact about the scope, because the word repair invites far more than this can do. What gets rebuilt is the index, not the contents. Objects that are genuinely not in the file cannot be reconstructed from a file that does not contain them, so a download that stopped halfway comes back as far as it got, at best. A file with no trailer dictionary, or one that never carried a PDF header at all, gives qpdf nothing to start from and it says so instead of handing you something. It does not undelete pages, recover text somebody removed, or reverse an edit. It is not a virus scanner and not a converter: a file that is not a PDF is reported as a file that is not a PDF. The most useful thing this page does is tell you the truth about your file afterwards. qpdf distinguishes between reading a document cleanly and having to reconstruct parts of it, and it reports each thing it worked around — a recovered object stream, a bad offset, an object it had to go looking for. Those warnings are shown rather than swallowed, so a file that had to be rebuilt is never presented as one that was fine all along, and when there was nothing to warn about the tool says the structure was already sound rather than claiming a rescue.
